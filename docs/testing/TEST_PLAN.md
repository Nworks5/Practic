# Тест-план приложения Timetracker

## 1. Объект тестирования
Timetracker — локальное десктоп-приложение для учёта времени студента: таймер задач, ведение задач и заметок, отчёты и фильтрация по датам.
## 2. Цели тестирования
Проверить корректность работы всех функций приложения (таймер, задачи, заметки, отчёты, фильтрация).
Проверить удобство и корректность интерфейса и переходов между экранами.
Проверить устойчивость к некорректным данным (пустые поля, отрицательные значения, длинные строки, спецсимволы).
Проверить соответствие требованиям производительности (отклик ≤ 1 с).
Проверить целостность данных в БД (связи, ограничения, атомарность, защита при сбое).
Проверить инициализацию БД при первом запуске и сохранность данных между запусками.
## 3. Области тестирования
Функциональное тестирование (работают ли все функции).
Тестирование интерфейса (удобно ли пользователю).
Тестирование устойчивости к ошибкам (корректно ли обрабатываются некорректные данные).
Тестирование производительности (отвечает ли приложение требованиям по скорости).
Тестирование целостности данных (корректно ли работают связи в БД).
## 4. Уровни критичности дефектов
Критический — приложение падает, данные теряются, функция полностью неработоспособна.
Значительный — функция работает, но с существенными ошибками, обходные пути сложны.
Незначительный — функция работает, но есть мелкие недочёты (неудобный текст, неточное форматирование).
Рекомендация — не ошибка, но можно улучшить.
## 5. Критерии начала тестирования
Код собран, приложение запускается 
Схема БД загружается без синтаксических ошибок.
Подготовлен скрипт наполнения тестовыми данными, выполняемый без ошибок.
Тестовые данные зафиксированы.
## 6. Критерии завершения тестирования
1. Все тест-кейсы из TEST_CASES.md выполнены, результаты записаны.
2. Каждая функция брифа покрыта минимум 3 кейсами; покрыты все бизнес-операции, CRUD сущностей, внешние ключи, инициализация, сохранность между запусками и некорректный ввод.
3. Не осталось открытых дефектов уровня «Критический» и «Значительный».
4. Проверены все критерии приёмки брифа (запрет пустых полей, защита при сбое, работа таймера, фильтрация, отчёт, отклик ≤ 1 с).

## 7. Требования к тестовым данным
**Изоляция и воспроизводимость**. Перед каждым кейсом БД сбрасывается и наполняется базовым состоянием, поэтому кейсы независимы и выполняются в любом порядке.
**Конкретность**. Во всех кейсах используются точные значения 
**Единицы.** duration хранится в минутах.
