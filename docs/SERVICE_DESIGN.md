# Описание работы программы (Бизнес-логика Timetracker)

## 1. Обзор слоя бизнес-логики

Бизнес-логика находится между экранами приложения и базой данных (DAO). 
* Проверяет входные данные.
* Объединяет несколько шагов в одну задачу.
* Отменяет операцию (`ROLLBACK`) при сбое базы данных.

## 2. Описание бизнес-операций

### Операция 1: Остановка таймера и сохранение времени (`stopAndSaveTimer`)

* **Входные данные:** `taskId` (номер задачи), `stopTime` (время нажатия кнопки «Стоп»).
* **Результат:** `true` (успех) или `false` (ошибка).
* **Используемые SQL-запросы:**
  * `SELECT timer_id, task_id, start_time FROM timer WHERE task_id = ?;`
  * `INSERT INTO time_logs (task_id, start_time, duration, end_time) VALUES (?, ?, ?, ?);`
  * `DELETE FROM timer WHERE timer_id = ?;`

#### Проверки перед выполнением:
* Номер задачи должен быть больше нуля.
* Время кнопки «Стоп» не может быть раньше времени старта таймера.

#### Обработка ошибок:
* При нарушении правил операция отменяется, пользователю выводится предупреждение.
* При сбое БД срабатывает отмена (`ROLLBACK`). Таймер остается тикать в базе.

#### Алгоритм:

function stopAndSaveTimer(taskId, stopTime):
    if taskId <= 0:
        показать_пользователю("Неверный номер задачи")
        return false
        
    ОТКРЫТЬ_ТРАНЗАКЦИЮ
    try:
        active_timer = timer.getById(taskId)
        if active_timer == NULL:
            показать_пользователю("Активный таймер не найден")
            ОТМЕНИТЬ_ТРАНЗАКЦИЮ
            return false
            
        duration = посчитать_минуты(active_timer.start_time, stopTime)
        if duration <= 0:
            показать_пользователю("Время стопа не может быть раньше старта")
            ОТМЕНИТЬ_ТРАНЗАКЦИЮ
            return false
            
        time_logs.insert(active_timer.task_id, active_timer.start_time, duration, stopTime)
        timer.delete(active_timer.timer_id)
        
        ПОДТВЕРДИТЬ_ТРАНЗАКЦИЮ
        return true
    except ОшибкаБД:
        ОТМЕНИТЬ_ТРАНЗАКЦИЮ
        показать_пользователю("Ошибка БД. Таймер не сброшен, минуты сохранены.")
        return false


### Операция 2: Безопасное удаление задачи (`safeDeleteTask`)

* **Входные данные:** `taskId` (номер задачи).
* **Результат:** `true` (удалено) или `false` (удаление запрещено).
* **Используемые SQL-запросы:**
  * `SELECT COUNT(*) AS "Количество логов" FROM time_logs WHERE task_id = ?;`
  * `DELETE FROM task WHERE task_id = ?;`

#### Проверки перед выполнением:
* Если количество записей времени по задаче больше 0, удаление блокируется.

#### Обработка ошибок:
* Если у задачи есть история, операция отменяется, пользователю выводится предупреждение.

#### Алгоритм:

function safeDeleteTask(taskId):
    try:
        logs_count = countTaskTimeLogs(taskId)
        if logs_count > 0:
            показать_пользователю("Нельзя удалить запись задач уже с существующими записями времени")
            return false
            
        task.delete(taskId)
        return true
    except ОшибкаБД:
        показать_пользователю("Сбой базы данных при удалении")
        return false

### Операция 3: Фильтрация отчета по датам (`getFilteredTimeReport`)

* **Входные данные:** `startDate` (дата начала), `endDate` (дата конца).
* **Результат:** Список строк с названиями задач и минутами.
* **Используемые SQL-запросы:**

  SELECT t.task_text AS "Название задачи", SUM(tl.duration) AS "Общее время (мин)"
  FROM task t
  JOIN time_logs tl ON t.task_id = tl.task_id
  WHERE tl.start_time BETWEEN ? AND ?
  GROUP BY t.task_id, t.task_text
  ORDER BY SUM(tl.duration) DESC;


#### Проверки перед выполнением:
* Поля дат не должны быть пустыми.
* Начальная дата не может быть позже конечной.

#### Обработка ошибок:
* При неверных датах запрос не отправляется, выводится ошибка. Если за период нет записей, возвращается пустой список.

#### Алгоритм:

function getFilteredTimeReport(startDate, endDate):
    if startDate == "" or endDate == "":
        показать_пользователю("Поля дат не должны быть пустыми")
        return []
    if startDate > endDate:
        показать_пользователю("Некорректный диапазон дат")
        return []
        
    try:
        return выполнить_sql_фильтр(startDate, endDate)
    except ОшибкаБД:
        показать_пользователю("Не удалось загрузить отчет из-за ошибки БД")
        return []


### Операция 4: Получение отчета по задачам за месяц (`getMonthlyTotalReport`)

* **Входные данные:** `monthStartDate` (дата начала месяца).
* **Результат:** Список задач и их минут за месяц.
* **Используемые SQL-запросы:**

  SELECT t.task_text AS "Задача", SUM(tl.duration) AS "Всего минут за месяц"
  FROM task t
  JOIN time_logs tl ON t.task_id = tl.task_id
  WHERE tl.start_time >= ?
  GROUP BY t.task_id, t.task_text
  ORDER BY SUM(tl.duration) DESC;


#### Проверки перед выполнением:
* Дата начала месяца не должна быть пустой.

#### Обработка ошибок:
* Если данных за месяц нет, система возвращает пустой список.

#### Алгоритм:

function getMonthlyTotalReport(monthStartDate):
    if monthStartDate == "":
        показать_пользователю("Дата начала месяца не указана")
        return []
        
    try:
        report = выполнить_sql_месяц(monthStartDate)
        return report
    except ОшибкаБД:
        показать_пользователю("Ошибка построения отчета за месяц")
        return []

## 3. Тест-кейсы

### Тесты для Операции 1 (Остановка таймера)

* **Тест-кейс 1.1: Успешный сценарий**
  * **Входные данные:** `taskId = 1`, Старт в `12:00:00`, Стоп в `12:45:00`.
  * **Ожидаемое поведение:** Программа считает разницу (45 минут), записывает строку в историю и удаляет текущий таймер.
  * **Ожидаемый результат:** Таймер остановлен, в истории появилось 45 минут.
* **Тест-кейс 1.2: Сценарий с некорректными входными данными**
  * **Входные данные:** `taskId = 1`, Старт в `12:00:00`, Стоп в `11:30:00`.
  * **Ожидаемое поведение:** Программа видит отрицательное время, останавливает операцию и показывает предупреждение.
  * **Ожидаемый результат:** Выведена ошибка времени, данные в БД не изменились.
* **Тест-кейс 1.3: Сценарий с ошибкой БД**
  * **Входные данные:** `taskId = 1`, Старт в `12:00:00`, Стоп в `12:45:00`, база данных заблокирована.
  * **Ожидаемое поведение:** Программа ловит сбой на шаге записи истории, делает `ROLLBACK` и отменяет удаление таймера.
  * **Ожидаемый результат:** Сообщение «Ошибка БД». Таймер остался в базе.
